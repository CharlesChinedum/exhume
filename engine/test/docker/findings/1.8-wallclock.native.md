# 1.8 Risk 7: wall-clock time of discovery with recording on (native)

**PASS**

- Mode: **native**. PASS decision uses this native total.
- forge: forge Version: 1.5.1-stable
- Config: runs=256, depth=64, fail_on_revert=true, shrink_run_limit=0, gas_limit=1000000000, --fuzz-seed 42, GAS_CAP=10,000,000 per call, legacy optimizer off. foundry.toml uses the 1.5 scheme (exact pins, per-file restrictions) and the 1.7 scheme (remappings.txt, allow_paths, absolute forge-std restriction).
- Handler: two functions (`handler_transfer`, `handler_batchTransfer`), each makes per call: one capped low-level call to the legacy deployment and one to the port deployment (same sender, calldata, value, warp/roll), two capped `staticcall` balanceOf reads (actor on each side), `vm.recordLogs` + `vm.getRecordedLogs` per side, `vm.deal` before each side when ether is attached (about 1 in 8 transfer calls, both sides revert as the functions are non-payable), a comparison of success flags, return data, log hashes and state reads, a classification, and one `vm.writeLine` of one JSON line (about 980 bytes). batchTransfer uses a targeted value `max/cnt + 1` for about half of its calls with cnt >= 2.
- Deviation from the design's handler, worst case for timing: the benchmark does not set `stopped` after an `exorcised` record, so every call does the full work and every sequence writes depth lines. It writes no setup (idx == -1) records, so the expected line count is exactly runs*depth + depth.
